# 기술 스택 개요

비개발자도 "지금 뭘로 만들고 있는지" 감을 잡을 수 있게 정리한 문서. 각 조각이
왜 이걸 썼는지까지 적어서, 나중에 바꿀 때 판단 기준으로 쓸 수 있게 한다. 더 깊은
구현 디테일은 [`architecture-notes.md`](./architecture-notes.md) 참고.

## 지금 실제로 쓰고 있는 것

| 영역 | 선택 | 왜 |
|---|---|---|
| 백엔드 프레임워크 | NestJS (Node.js) | 구조화된 모듈/DTO/가드 패턴이 있어서 혼자 개발해도 코드가 흩어지지 않음. 젤리에서도 검증된 선택. |
| DB | PostgreSQL + Prisma ORM | 관계형 데이터(구독/메시지/정산)에 적합, Prisma가 스키마-코드 동기화를 자동화. |
| 앱 | Expo (React Native) + expo-router | iOS/Android 동시 개발, OTA 업데이트로 스토어 심사 없이 일부 수정 배포 가능. |
| 앱 상태관리/서버통신 | TanStack Query | 서버 데이터 캐싱/재검증을 직접 구현 안 해도 됨. |
| 인증 | JWT + 소셜 로그인 예정(Google/Apple/Naver/Kakao/Line) | `JwtStrategy`가 매 요청마다 DB에서 유저를 다시 읽어와서, 정지/차단된 유저가 예전 토큰으로 계속 접근하는 걸 막음. |
| 인앱결제 | Apple StoreKit2(`@apple/app-store-server-library`) + Google Play Developer API | 앱스토어 정책상 디지털 구독은 자체 결제(Stripe 등) 불가, IAP 필수. |
| 푸시 알림 | Firebase Cloud Messaging(FCM) | 사실상 업계 표준, iOS/Android 동시 지원. |
| 이메일 | Resend(REST API 직접 호출) | SDK 없이 fetch 하나로 끝나는 가벼운 트랜잭션 이메일 서비스 — 부모 동의 메일 등에 사용. |
| 정기 작업(cron) | `@nestjs/schedule` | 스토리 만료 정리, 대화기록 보존기간 정리 등 백엔드 프로세스 안에서 도는 가벼운 스케줄러. |
| 번역 | Google Cloud Translation API (예정, 2026-09-21 확정) | 태국어/한국어/영어를 전부 지원해야 해서 선택 — DeepL은 태국어 미지원. |

## 아직 정해지지 않은 것 (결정 필요)

- **호스팅/배포 인프라**: 백엔드를 어디에 올릴지(예: Railway, Render, Fly.io, AWS 등)
  아직 정한 적 없음. CI/CD(`.github/workflows`)도 없음.
- **파일(사진/음성/영상) 스토리지**: Supabase Storage, Cloudflare R2, AWS S3 같은 실제
  파일 저장소가 코드에 연동돼 있지 않음 — 배우가 미디어를 업로드하는 기능 자체가
  화면조차 아직 없는 이유 중 하나.
- **에러 모니터링(Sentry)**: 미연동. 지금은 에러가 나도 로그에만 남고 알림이 안 감.
- **캐시/Redis**: 아직 필요 없다고 판단해서 안 씀(트래픽 규모가 작아서).

이 목록은 `architecture-notes.md`의 "젤리 대비 갭" 표와 같은 내용을 이 문서
관점(전체 스택 조망)에서 다시 정리한 것.

## 인프라 비용 추정 — 배우/소속사 10팀 규모 기준 (2026-09-21, 참고용 추정치)

**주의**: 실제 호스팅/스토리지 공급자를 아직 안 정했기 때문에 정확한 견적이 아니라
일반적인 소규모 SaaS 기준의 어림값이다. 실제 공급자를 정하면 이 표를 갱신할 것.

| 항목 | 월 예상 비용(대략) | 비고 |
|---|---|---|
| DB 호스팅(관리형 Postgres) | $25~50 | Supabase/Neon/Railway 소형 플랜 기준. 10팀 규모면 아직 여유 있는 티어. |
| 백엔드 서버 호스팅(dev+prod) | $20~50 | Render/Railway 같은 PaaS 기준, 서버리스면 더 저렴할 수 있음. |
| 파일 스토리지 + CDN(사진/음성/영상) | $30~150 | 미디어 볼륨에 따라 편차가 가장 큼 — 배우가 영상을 자주 올릴수록 급격히 증가. |
| 푸시 알림(FCM) | $0 | 무료. |
| 이메일(Resend) | $0~20 | 무료 티어 초과 시. |
| 번역 API(Google) | $5~20 | 문자 수 기준 과금, 캐싱하므로 반복 비용 적음. |
| 에러 모니터링(Sentry, 미연동) | $0~26 | 무료 티어로 시작 가능. |
| 도메인/SSL | ~$1 | 연 단위 환산. |
| **합계(대략)** | **$80~320/월 (약 11만~44만원)** | 미디어 볼륨이 지배적 변수. |

여기엔 **앱스토어/플레이스토어 수수료(매출의 15~30%)는 포함 안 됨** — 그건 인프라
비용이 아니라 매출 배분이라 별도로 계산해야 함(`business-faq.md`의 소속사 정산
논의 참고).

## `{{name}}` 개인화 치환 — 이미 구현됨

`Message.body`에 `{{name}}` 플레이스홀더를 넣으면, 팬이 메시지를 조회하는 시점에
요청한 팬 본인의 `displayName`으로 서버가 치환해서 내려준다(Bubble의 개인화 메시지
방식과 동일). 배우는 방송 메시지 하나만 작성하면 되고, 팬마다 실제로 저장되는 행이
따로 있는 게 아니라 조회 시점 치환이라 저장 공간도 아낀다. 이미 구현 완료 — 추가
작업 필요 없음.
