# 기술 스택 개요

"토피가 뭘로 만들어져 있고, 왜 그걸 골랐고, 돈이 드는지"를 한 번에 보는 문서(2026-09-29 전면 개정 —
예전 판은 파일 저장소 미연동·번역 Google 등 지난 내용이었음). 비용 합계·사업 비용은
[`docs/product/cost-overview.md`](../product/cost-overview.md), 구현 세부는 [`architecture-notes.md`](./architecture-notes.md).

- 비용 칸: **무료** = 오픈소스이거나 무료 서비스 / **유료** = 쓰는 만큼 또는 월정액. 가격은 2026년 기준 어림값이고
  가입할 때 다시 확인할 것.
- 상태 칸: **동작 중** = 지금 로컬에서 실제로 돌아감 / **키 대기** = 코드는 완료, 계정·키만 넣으면 됨 / **미정** = 아직 안 고름.

---

## 1. 한눈에 보기

```
[팬·스타·소속사·운영자 앱 (Expo / React Native, iOS·Android·웹 하나의 코드)]
        │  HTTPS(JSON) — 로그인 토큰(JWT) 첨부
        ▼
[백엔드 서버 (NestJS, Node.js)] ──── [PostgreSQL DB (Prisma로 접근)]
        │
        ├─ 파일: Cloudflare R2 (사진·음성·영상) — 앱이 서버가 준 임시 주소로 직접 올리고 받음
        ├─ 푸시: Firebase Cloud Messaging → 애플/구글 푸시
        ├─ 메일: Resend (부모 동의 메일)
        ├─ 결제 확인: 애플 App Store / 구글 Play 서버
        ├─ 소셜 로그인 확인: 구글·애플·네이버·카카오·라인 서버
        └─ 오류 수집: Sentry (앱·서버 둘 다)
```

앱은 **하나**다. 로그인한 계정의 역할(팬/스타/소속사 직원/운영자)에 따라 다른 화면이 나온다.

| **TanStack Query** | 서버 데이터 받아오기·캐시·새로고침 | "5초마다 새 메시지 확인", "위로 올리면 이전 대화 더 받기" 같은 걸 직접 구현 안 해도 됨 | 무료 |

## 3. 백엔드 서버 (`backend/`)

| 기술 | 하는 일 | 왜 골랐나 | 비용 |
|---|---|---|---|
| **NestJS (Node.js, TypeScript)** | API 서버 전체 | 기능별 모듈·입력 검사(DTO)·권한 검사(가드) 틀이 정해져 있어 혼자 만들어도 코드가 안 흩어짐. 젤리에서 검증됨. 앱과 같은 TypeScript라 언어 하나로 개발 | 무료 |
| **PostgreSQL 16** | 데이터베이스(회원·구독·메시지·신고 등) | 구독·결제·정산처럼 서로 얽힌 데이터에 맞는 관계형 DB. 가장 흔해서 어느 호스팅에서나 지원 | 무료(호스팅 비용은 아래) |
| **Prisma 7** | DB 구조 정의·마이그레이션·쿼리 | 스키마 파일 하나로 DB 구조와 코드 타입을 같이 관리 | 무료 |
| **JWT(passport-jwt) + 소셜 로그인 확인** | 로그인 유지, 구글·애플·네이버·카카오·라인 로그인 | 앱이 받아 온 소셜 토큰을 서버가 각 회사 서버에 직접 확인한 뒤 우리 토큰(JWT)을 발급. 요청마다 DB에서 계정을 다시 읽어서 정지된 계정은 바로 막힘 | 무료(각 소셜 로그인 자체도 무료 — `docs/product/cost-overview.md`) |
| **@aws-sdk/client-s3 (S3 방식)** | 파일 저장소와 통신 | R2가 아마존 S3와 같은 방식이라 표준 라이브러리 그대로 사용. 나중에 S3 등으로 바꿔도 설정값만 바꾸면 됨 | 무료 |
| **file-type** | 올린 파일이 진짜 사진·음성·영상인지 확인 | 확장자만 바꾼 가짜 파일을 파일 내용(앞부분 바이트)으로 걸러냄 | 무료 |
| **firebase-admin** | 푸시 보내기(500건씩 묶음) | FCM 공식 서버 라이브러리 | 무료 |
| **@apple/app-store-server-library + google-auth-library** | 결제 영수증 확인 | 애플 공식 라이브러리, 구글 Play 개발자 API 인증 | 무료 |
| **Resend(직접 호출)** | 부모 동의 메일 발송 | 라이브러리 없이 요청 하나로 끝남 | 월 3,000통 무료 — **키 대기** |
| **@nestjs/schedule** | 매일 새벽 정리 작업(1년 지난 대화, 안 쓰는 파일, 만료 스토리) | 서버 안에서 도는 가벼운 예약 작업. 따로 작업 서버가 필요 없음 | 무료 |
| **@nestjs/throttler, ValidationPipe** | 요청 횟수 제한, 입력값 검사 | 무차별 요청·이상한 입력 차단(기본 보안) | 무료 |
| **Sentry(@sentry/nestjs)** | 서버 오류 수집 | 앱과 같은 곳에서 같이 봄 | 무료 플랜 — **키 대기** |
| **오류 문구 다국어** | 서버 오류를 팬의 언어로 | 앱이 보낸 언어 정보(Accept-Language)를 보고 6개 언어 중 골라 응답 | 무료(직접 구현) |

## 4. 파일 올리기·보기는 이렇게 동작함

1. 스타가 사진·영상을 고르면 앱이 서버에 "올릴 주소 주세요"라고 요청.
2. 서버가 **몇 분만 유효한 업로드 전용 주소**(presigned URL)를 줌 → 앱이 그 주소로 **R2에 직접** 올림(진행률 표시·취소 가능).
   서버를 거치지 않아서 서버가 큰 영상 때문에 느려지지 않음.
3. 서버가 올라간 파일의 실제 형식·크기를 확인한 뒤 메시지에 붙임(사진 20MB·음성 30MB·영상 200MB, 잠정).
4. 팬이 볼 때는 서버가 "이 팬이 구독 중인지" 확인하고 **1~2시간만 유효한 보기 주소**를 줌 → 주소가 밖으로 새도 곧 만료.
5. **왜 Cloudflare R2**: 팬에게 보내는 전송량(다운로드)이 **무료**라 영상이 많은 서비스에 가장 싸다(AWS S3는 전송량 과금).
   저장 요금 GB당 월 약 $0.015, 10GB까지 무료.
6. 로컬 개발은 R2 대신 MinIO 같은 가짜 S3를 띄워서 씀(설정값만 다름).

## 6. 아직 안 정한 것

| 항목 | 지금 | 메모 |
|---|---|---|
| **서버·DB 호스팅** | **미정** | Railway·Render·Fly.io 같은 간편 호스팅 + 관리형 Postgres(자동 백업) 추천 방향. 출시 초기엔 작은 서버 1대로 충분 — 서버 부담은 배우 수보다 **팬 수**가 좌우 |
| **실시간 채팅** | 채팅방을 열어 두면 5초마다(스타 답장 화면 3초) 새로 확인 | 호스팅과 무관하게 만들 수 있는 방법(Postgres 알림 기능 LISTEN/NOTIFY + SSE)이 있어 앞당길 수 있음 — Redis 같은 추가 서비스 불필요 |
| **메시지 번역(2차)** | "LLM으로" 까지만 결정 | Claude/GPT/Gemini 중 실제 대화 샘플로 비교 후 선택. 누른 번역만 한 번 번역해서 저장(비용 절약) |
| **캐시(Redis)** | 안 씀 | 지금 규모엔 불필요 |

## 부록 — `{{name}}` 개인화 치환 (구현됨)

`Message.body`에 `{{name}}`을 넣으면 팬이 메시지를 볼 때 그 팬의 닉네임으로 바꿔서 내려준다(버블 방식). 팬마다
메시지를 따로 저장하지 않고 볼 때 바꾸는 거라 저장 공간도 아낀다.
