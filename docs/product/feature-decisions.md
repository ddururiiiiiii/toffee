# 제품 기능 결정 사항

지금까지 논의를 거쳐 확정된 제품 결정들을 주제별로 정리한다. "왜 이렇게 정했는지"까지
적어서, 나중에 다시 논의할 때 같은 논의를 반복하지 않도록 한다. 기술적인 구현 방법은
[`docs/engineering/architecture-notes.md`](../engineering/architecture-notes.md) 참고.

## 메시지·스토리는 배우 본인만 보낸다

처음엔 소속사 담당자가 배우 대신 메시지를 발송하는 구조였지만, **소속사의 발송 권한을
완전히 없애고 배우 본인만 메시지·스토리를 보낼 수 있게** 바꿨다(2026-09-18). 이유:
소속사가 배우 이름으로 대신 말하는 구조를 보수적으로 열어두고 싶지 않다는 판단.

- 대신 소속사는 **"배우가 실제로 뭘 보내고 있는지" 읽기 전용으로 모니터링**할 수 있어야
  한다 — 팬이 보는 화면 그대로, 콘텐츠 품질 관리 목적. 새 메시지/스토리가 나가면 소속사
  담당자에게 알림도 가야 한다.
- 소속사 콘솔은 웹이 메인이지만, 이 모니터링/알림만큼은 앱에서도 볼 수 있어야 한다 —
  담당자가 자리를 비웠을 때도 확인할 수 있어야 하기 때문.

서버 쪽(알림 발송 + 배우가 보낸 내용 조회 API)은 구현 완료(2026-09-18). 소속사
콘솔(앱)의 "발송" 탭도 이제 이 API로 보여주는 읽기 전용 "모니터링" 탭으로
바뀌었다(소속사는 이제 발송 권한이 없으니까). 다만 이건 지금 앱 화면 하나로만
되어 있고, 별도 데스크톱용 웹 화면은 아직 없음(원래 계획한 "웹이 메인" 방침은
그대로 유효, 구현만 아직).

## 운영자(ADMIN) 화면 — 구현 완료 (2026-09-18)

원래 운영자는 API 권한만 있고 화면이 하나도 없었다(신고 처리 기능조차 화면 없이
방치돼 있었음). 이번에 콘텐츠 모더레이션/회원 관리 작업과 같이 앱 화면을 만들어서
해결 — 신고 처리, 금칙어 관리, 회원 정지/차단을 이제 운영자가 앱에서 직접 쓸 수
있다. 소속사와 똑같이 지금은 앱 화면만 있고 데스크톱 웹 화면은 아직 없음(파일럿
단계엔 앱만으로 충분하다고 판단, 필요해지면 웹도 추가).

**계정 구조(2026-09-18 확정)**: 계정 하나에 역할(role) 하나만 붙는다 — 소속사
담당자/운영자와 똑같은 방식으로, 배우 본인도 전용 계정으로 로그인하면 자동으로
배우 전용 화면으로 들어간다(별도 앱 아님, 같은 토피 앱). 배우가 개인적으로 다른
배우를 팬처럼 구독해보고 싶다면 완전히 다른 계정(다른 이메일 등)으로 새로 가입해야
한다 — 한 계정으로 "배우 모드/팬 모드"를 오가는 기능은 만들지 않는다(파일럿 단계엔
과함). 백엔드 쪽 계정 구조 자체는 구현 완료, 배우가 실제로 쓸 화면(사진/영상 촬영해서
올리는 화면 등)은 아직 안 만듦.

## 24시간 소멸 스토리 기능

인스타그램 스토리처럼 24시간 뒤 사라지는 기능을 추가하기로 함(2026-09-18). 확정된 스펙:

- 업로드는 배우 본인이 앱에서 직접 한다(소속사 콘솔에서는 못 올림).
- 노출 시간은 24시간 고정 — 소속사가 시간을 조절하게 하지 않는다.
- 누가 봤는지(조회한 팬 목록)까지 배우/소속사가 확인할 수 있다.
- 구독자만 볼 수 있다 — 비구독자에게 미리보기를 열어주지 않는다(메시지와 같은 정책).

서버 쪽 구현은 완료(2026-09-18). 다만 배우가 실제로 스토리를 찍어 올리는 화면은
아직 없어서, 지금은 개발자가 직접 데이터를 넣어야 확인 가능한 상태.

**덤으로 버그 하나 고침**: 원래 "배우는 사진/음성/영상을 보낼 수 있다"고 기획돼
있었는데, 실제로는 영상(비디오) 전송이 아예 안 되는 상태였다. 스토리 작업 중
발견해서 메시지·스토리 둘 다 영상을 보낼 수 있게 고쳤다.

## 라이브 방송은 나중으로 미룸

인스타 스토리 기능과 같이 요청됐던 라이브 방송은 **당장은 만들지 않기로 결정**
(2026-09-18) — 실시간 스트리밍은 완전히 새로운 인프라가 필요해서 배우 1명 파일럿
단계에는 과하다고 판단. 스토리 기능을 먼저 검증하고 다시 논의한다.

## 소속사 콘솔 — 뭘 보여주고 뭘 못 하게 할지

| 기능 | 소속사가 할 수 있나 |
|---|---|
| 메시지·스토리 발송 | ❌ (배우 본인만) |
| 배우가 보낸 걸 읽기 전용으로 모니터링 | ✅ (신규 요구사항) |
| 팬 답장 열람 | ✅ |
| 구독자 수/발송 통계 | ✅ |

| 신고 처리 | ❌ (플랫폼 운영자만, 이해상충 방지 목적) |

## 브랜드/화면 방향

브랜드 톤, 컬러, 화면 구조(하단 탭 3개, 배우 프로필에 콘텐츠 피드 없음 등)는
[`brand-guide.md`](./brand-guide.md)에 정리.

## 콘텐츠 모더레이션 (2026-09-18 확정)

팬이 배우에게 보내는 답장에 금칙어(욕설/음란한 표현)가 있으면:

- **전송 자체를 차단**한다 — 배우에게는 아예 도달하지 않고, 팬에게 "전송되지 않았다"고
  알린다. 마스킹(`***` 치환) 방식은 쓰지 않는다.
- 금칙어 목록은 **한국어·태국어·영어** 3개 언어로 관리한다. 한국어를 포함한 이유는
  운영자(대표) 본인이 직접 목록을 관리하기 편하도록.
- "블랙리스트 관리"는 **금칙어 목록 관리**를 뜻한다(특정 팬 계정을 통째로 차단하는
  기능과는 별개 — 아래 회원 관리 참고).

## 회원(팬) 관리 (2026-09-18 확정)

운영자가 문제 있는 팬 계정을 제재할 수 있어야 한다. 제재는 2단계:

1. **일시정지** — 정해진 기간 동안 서비스 이용 불가
2. **영구차단** — 계정을 완전히 막음

가벼운 위반은 일시정지, 심각한 위반은 영구차단으로 운영자가 상황 보고 선택한다.

**둘 다 구현 완료(2026-09-18)** — 금칙어 관리·회원 정지/차단·신고 처리를 운영자가
실제로 쓸 수 있는 화면(앱)까지 다 만들었다. 원래 신고 처리 기능조차 화면이 없어서
API로만 쓸 수 있었는데, 이번에 같이 해결함. 앱 로그인 후 운영자 계정은 이제
전용 화면(`/admin`)으로 바로 들어간다.

## 연령 정책: 만 14세 미만은 부모 동의 (2026-09-18 확정, Bubble 방식 따름)

Bubble의 실제 약관을 확인해보니 "만 14세 미만은 막지 않고 법정대리인 동의를 받는다"고
돼 있어서, 토피도 같은 방식으로 가기로 함(한국 개인정보보호법 요건과도 일치).
가입 시 생년월일을 물어보고, 14세 미만이면 부모 이메일로 확인 링크를 보내서 동의를
받는다 — 동의 전까지는 구독(결제)이 막힌다. 구현 완료.

## 이용약관 / 개인정보처리방침 화면 (2026-09-18, 초안)

앱 안에 실제로 볼 수 있는 화면을 만들었다(Profile 탭에서 링크). **다만 내용은
초안이고 화면에도 그렇게 표시되어 있음** — 정식 출시 전에 변호사 검토가 필요하다.
아직 소셜 로그인 화면 자체가 없어서, "약관에 동의합니다" 체크박스는 소셜 로그인
UI를 만들 때 같이 붙여야 한다.
