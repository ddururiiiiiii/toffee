# 제품 기능 결정 사항

지금까지 논의를 거쳐 확정된 제품 결정들을 주제별로 정리한다. "왜 이렇게 정했는지"까지
적어서, 나중에 다시 논의할 때 같은 논의를 반복하지 않도록 한다. 기술적인 구현 방법은
[`docs/engineering/architecture-notes.md`](../engineering/architecture-notes.md) 참고.

## 메시지·스토리는 배우 본인만 보낸다

처음엔 소속사 담당자가 배우 대신 메시지를 발송하는 구조였지만, **소속사의 발송 권한을
완전히 없애고 배우 본인만 메시지·스토리를 보낼 수 있게** 바꿨다(2026-09-18). 이유:
소속사가 배우 이름으로 대신 말하는 구조를 보수적으로 열어두고 싶지 않다는 판단.

- 대신 소속사는 **"배우가 실제로 뭘 보내고 있는지" 읽기 전용으로 모니터링**할 수 있어야
  한다 — 팬이 보는 화면 그대로, 콘텐츠 품질 관리 목적. 새 메시지/스토리가 나가면 소속사
  담당자에게 알림도 가야 한다.
- 소속사 콘솔은 웹이 메인이지만, 이 모니터링/알림만큼은 앱에서도 볼 수 있어야 한다 —
  담당자가 자리를 비웠을 때도 확인할 수 있어야 하기 때문.

## 24시간 소멸 스토리 기능

인스타그램 스토리처럼 24시간 뒤 사라지는 기능을 추가하기로 함(2026-09-18). 확정된 스펙:

- 업로드는 배우 본인이 앱에서 직접 한다(소속사 콘솔에서는 못 올림).
- 노출 시간은 24시간 고정 — 소속사가 시간을 조절하게 하지 않는다.
- 누가 봤는지(조회한 팬 목록)까지 배우/소속사가 확인할 수 있다.
- 구독자만 볼 수 있다 — 비구독자에게 미리보기를 열어주지 않는다(메시지와 같은 정책).

## 라이브 방송은 나중으로 미룸

인스타 스토리 기능과 같이 요청됐던 라이브 방송은 **당장은 만들지 않기로 결정**
(2026-09-18) — 실시간 스트리밍은 완전히 새로운 인프라가 필요해서 배우 1명 파일럿
단계에는 과하다고 판단. 스토리 기능을 먼저 검증하고 다시 논의한다.

## 소속사 콘솔 — 뭘 보여주고 뭘 못 하게 할지

| 기능 | 소속사가 할 수 있나 |
|---|---|
| 메시지·스토리 발송 | ❌ (배우 본인만) |
| 배우가 보낸 걸 읽기 전용으로 모니터링 | ✅ (신규 요구사항) |
| 팬 답장 열람 | ✅ |
| 구독자 수/발송 통계 | ✅ |
| 매출/정산 통계 | 아직 없음 — 계약 협상 이후 필요해질 항목 |
| 신고 처리 | ❌ (플랫폼 운영자만, 이해상충 방지 목적) |

## 브랜드/화면 방향

브랜드 톤, 컬러, 화면 구조(하단 탭 3개, 배우 프로필에 콘텐츠 피드 없음 등)는
[`brand-guide.md`](./brand-guide.md)에 정리.

## 진행 중 — 아직 정하는 중인 것

- **콘텐츠 모더레이션**: 팬이 배우에게 욕설/음란한 표현을 보내지 못하게 막는 기능,
  그리고 운영자가 회원(팬)을 정지/차단하고 금칙어 목록을 관리하는 기능 — 논의 시작함,
  세부 방식은 아직 미정.
